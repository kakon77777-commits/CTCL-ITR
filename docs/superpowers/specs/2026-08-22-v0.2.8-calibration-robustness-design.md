# CTCL-ITR v0.2.8 Calibration Robustness, Drift & Task-Family Profiles — Design

## Purpose

v0.2.7 derives evidence-backed Autonomy and Governance Horizons from repeated trials. v0.2.8 makes those calibrated quantities comparable across time, task-family composition, and execution backends without silently treating every Horizon change as capability change.

The release remains read-only and non-authoritative:

```text
Calibration Drift != Capability Attribution
Robustness Report != Policy Decision
Comparison Signal != Authority
Composition Adjustment != Causal Identification
```

## Why this slice exists

A measured Horizon can move because the evaluated system changed, but it can also move because:

- the task-family mixture changed;
- one family received many more trials than another;
- the backend or scaffold changed;
- the benchmark/sample version changed;
- one family became unsupported at the target reliability;
- the common depth support changed.

v0.2.8 therefore makes the measurement context and task-family stratification first-class runtime artifacts.

## Architectural boundary

v0.2.8 does **not** modify the v0.2.7 calibrator. Instead it treats each v0.2.7 family profile as a calibrated evidence surface and builds comparison logic above it.

```text
Repeated Trials
  -> v0.2.7 Family Calibration
  -> CalibrationSnapshot
  -> Fixed-Reference Mixture
  -> Pairwise Robustness Comparison
  -> Drift / Composition Diagnostics
```

## CalibrationSnapshot

A snapshot records one calibration observation context:

- `snapshot_id`;
- `observed_at`;
- `backend_id`;
- `benchmark_id`;
- `benchmark_version`;
- `agent_config_id`;
- one shared v0.2.7 measurement contract;
- `family_suites`, keyed by task-family id.

Every family suite is calibrated independently using the existing `monotone_binomial_pava_v1` method. All families MUST share the same:

- unit;
- reliability target;
- scope id;
- assessment method.

The generated snapshot profile preserves the complete per-family v0.2.7 evidence profile.

## Task-family stratification

For subject $s \in \{A,G\}$ and family $f$, the snapshot exposes:

$$
H_{s,f}.
$$

A pairwise comparison reports:

$$
\Delta H_{s,f}=H^{(1)}_{s,f}-H^{(0)}_{s,f}
$$

only when both family profiles are supported. Unsupported families remain explicit instead of being imputed.

## Observed-mixture Horizon

The observed family weight for a subject is derived from trial mass:

$$
w^{obs}_{s,f}=\frac{N_{s,f}}{\sum_j N_{s,j}}.
$$

For each family, the PAVA fitted probability curve is linearly interpolated **inside its observed depth support only**. At depth $d$:

$$
p^{mix}_s(d)=\sum_f w_{s,f}p_{s,f}(d).
$$

The mixture Horizon is the target-reliability crossing of this weighted curve on the **common support intersection** of all positively weighted families.

No curve is extrapolated beyond a family's observed support.

## Composition standardization

The comparison spec provides fixed reference task-family weights:

$$
w^{ref}_f, \qquad \sum_f w^{ref}_f=1.
$$

The same reference weights are applied independently to both snapshots. This yields:

$$
H^{ref,(0)}_s, \qquad H^{ref,(1)}_s.
$$

The composition-adjusted drift is:

$$
\Delta H^{adj}_s=H^{ref,(1)}_s-H^{ref,(0)}_s.
$$

The observed-mixture drift is:

$$
\Delta H^{obs}_s=H^{obs,(1)}_s-H^{obs,(0)}_s.
$$

The composition residual is a descriptive decomposition:

$$
R^{comp}_s=\Delta H^{obs}_s-\Delta H^{adj}_s.
$$

`R_comp` is **not** claimed to be a causal effect. It only quantifies how much the observed-mixture delta differs from the fixed-reference-mixture delta under this explicit standardization.

## Composition shift

The family-mixture change is summarized using total-variation distance:

$$
TV_s=\frac12\sum_f\left|w^{obs,(1)}_{s,f}-w^{obs,(0)}_{s,f}\right|.
$$

This is reported separately for autonomy and governance.

## Robustness diagnostics

For each subject, v0.2.8 reports:

- base/current observed-mixture Horizon;
- observed-mixture delta;
- base/current reference-mixture Horizon;
- composition-adjusted delta;
- composition residual;
- observed-family-weight total variation;
- per-family Horizon deltas;
- supported-family fraction;
- family-direction agreement with the adjusted delta;
- base/current family Horizon range;
- maximum absolute family delta;
- elapsed seconds and descriptive adjusted delta/day when time advances.

Global context diagnostics report:

- `backend_changed`;
- `benchmark_version_changed`;
- `agent_config_changed`;
- `family_set_changed`;
- `comparison_kind`.

## Comparison kind

The reference implementation classifies comparison context without claiming causality:

- `longitudinal_same_configuration` — backend, benchmark version, and agent config unchanged;
- `cross_backend` — backend changed while benchmark version/config are stable;
- `mixed_configuration_change` — more than one major configuration axis changed.

## Support rules

A mixture Horizon is emitted only if:

1. every positively weighted family has a supported v0.2.7 subject profile;
2. all positively weighted family curves have a non-empty common depth-support intersection;
3. the weighted mixture curve brackets the target reliability inside that common support.

Otherwise the mixture result is explicit `unsupported` with reasons.

## Reference scenario

The canonical example contains two task families:

- `code` — higher Horizon;
- `research` — lower Horizon.

Between base and current snapshots:

- each family improves within-family;
- backend changes from `backend-alpha` to `backend-beta`;
- the observed trial mixture shifts from code-heavy to research-heavy;
- reference weights remain fixed at 50/50.

This creates a deliberately adversarial measurement case where observed-mixture drift can disagree with composition-adjusted drift.

The report must make that disagreement visible instead of flattening it into one headline number.

## Epistemic boundary

```text
Observed Horizon Delta != Capability Delta
Composition-Adjusted Delta != Backend-Causal Effect
Cross-Backend Comparison != Longitudinal Model Drift
Task-Family Average != Universal Capability
```

A fixed-reference mixture controls one explicitly modeled composition axis. It does not remove hidden task difficulty changes, backend effects, scaffold changes, evaluator drift, or other confounding.

## Compatibility

- v0.2.7 calibration suites/profiles remain unchanged;
- v0.2.6 Horizon/signal contracts remain unchanged;
- no TemporalEvent or governance schema changes;
- no authorization semantics change;
- no new runtime dependency.

## External-methodology note

The design is informed by current public task-horizon evaluation practice in which reliability is modeled as a function of task difficulty/duration and by 2026 warnings that Horizon estimates can become sensitive to modeling choices as task suites saturate. CTCL-ITR v0.2.8 does not claim methodological equivalence to METR and does not use their current logistic fit; it focuses on transparent task-family stratification and fixed-mixture comparison above the v0.2.7 empirical PAVA profile.

## Non-goals

v0.2.8 does not:

- infer causal backend improvement;
- merge distinct task families into one ontology;
- extrapolate family curves beyond observed support;
- bootstrap a Horizon confidence interval;
- automatically alter governance thresholds;
- grant/revoke authority or resume/suspend a run.
