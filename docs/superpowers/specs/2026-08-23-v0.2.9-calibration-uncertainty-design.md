# CTCL-ITR v0.2.9 — Calibration Uncertainty, Resampling & Drift Bands

## Status
Engineering design approved by continuation from v0.2.8.

## Goal
Add a deterministic, auditable resampling layer above v0.2.7 calibration and v0.2.8 robustness so Horizon and drift are represented with sampling-stability bands instead of point estimates only.

## Non-goals
- no new authority or governance mutation;
- no Bayesian posterior claims;
- no guarantee that percentile bands have exact frequentist coverage;
- no task-family composition resampling;
- no extrapolation beyond observed calibration support;
- no replacement of v0.2.7 PAVA or v0.2.8 mixture semantics.

## Method
Reference method id: `stratified_empirical_binomial_sha256_v1`.

For each replicate, snapshot, task family, subject, and observed depth:
1. preserve observed trial count `n`;
2. set empirical probability `p_hat = successes / n`;
3. deterministically generate `n` Bernoulli draws using SHA-256 counter-derived uniforms keyed by seed plus stable labels;
4. rebuild each family calibration suite;
5. rerun v0.2.7 PAVA calibration;
6. rebuild v0.2.8 snapshots and comparison;
7. retain supported Horizon/drift quantities and explicit unsupported outcomes.

The SHA-256 counter stream is used only for reproducibility, not cryptographic security.

## Bands
Supported scalar samples use a deterministic linear empirical quantile rule on sorted samples. For interval mass `q`, report:
- lower quantile `(1-q)/2`;
- median;
- upper quantile `1-(1-q)/2`;
- mean;
- supported replicate count/rate.

For drift quantities also report empirical sign shares among supported replicates:
`positive`, `negative`, `zero`.
These are resampling frequencies, not posterior probabilities.

## Conditioning
Task-family weights are held fixed:
- observed-mixture weights remain the observed trial-mass weights of each original snapshot;
- reference-mixture weights remain v0.2.8 comparison-spec weights.

Therefore v0.2.9 estimates outcome-sampling uncertainty conditional on composition. It does not absorb v0.2.8 composition residual into sampling uncertainty.

## Support discipline
A scalar band is emitted only if supported replicate rate is at least `minimum_supported_fraction`; otherwise the band remains null with `insufficient_resampling_support`.
Unsupported replicates remain counted by reason.

## Public API
`bootstrap_calibration_uncertainty(base_snapshot, current_snapshot, comparison_spec, uncertainty_spec) -> report`

## CLI
`ctcl-itr-calibration-uncertainty --base ... --current ... --comparison ... --uncertainty ...`

## Schemas
- `calibration-uncertainty-spec.schema.json`
- `calibration-uncertainty-report.schema.json`

## Core invariants
`Point estimate != uncertainty band`
`Bootstrap sign share != posterior probability`
`Resampling band != causal effect`
`Uncertainty report != authority`
`Conditional sampling uncertainty != composition uncertainty`
