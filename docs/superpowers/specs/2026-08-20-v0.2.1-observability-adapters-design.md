# CTCL-ITR v0.2.1 Observability Adapters Design

## Goal

Add two loss-conscious projections over canonical ATL events without changing ATL causal semantics:

1. ATL TemporalEvent -> CloudEvents 1.0 JSON envelope.
2. ATL event ledger -> OpenTelemetry-style span projection.

The ATL ledger remains canonical. Export formats are derived projections.

## CloudEvents adapter

`to_cloudevent(event)` maps:

- `event_id` -> `id`
- `source` -> `source`
- constant `1.0` -> `specversion`
- `event_type` -> `type` with prefix `org.evemiss.itr.`
- `subject` -> `subject`
- `occurred_at` -> `time`
- `application/json` -> `datacontenttype`
- ATL temporal-event schema URI -> `dataschema`
- full ATL event -> `data`

`from_cloudevent(envelope)` returns the original ATL event after checking the required CloudEvents context and the identity relationship `envelope.id == data.event_id`.

The adapter does not reinterpret or flatten ATL fields into CloudEvents extensions in v0.2.1. The complete ATL event stays under `data`, which guarantees lossless round-trip for the reference profile.

## OpenTelemetry-style projection

This slice does not depend on an OpenTelemetry SDK and does not emit OTLP wire payloads. It creates a deterministic span projection that a later SDK exporter can consume.

Each projected span contains:

- `event_id`
- `name`
- `span_kind`
- `trace_id`
- `span_id`
- `parent_span_id`
- `links[]`
- `start_time`
- `end_time`
- `status`
- `attributes`

Known GenAI operation mapping:

- `plan.*` -> `plan`
- tool actor / `tool.*` -> `execute_tool`
- agent/subagent operational events -> `invoke_agent`

ATL-specific fields are kept under `itr.*` attributes. Token budgets map to current GenAI usage attributes when present.

## Multi-parent semantics

ATL causality is a DAG and stays canonical.

- 0 causal parents -> no span parent, no links.
- 1 causal parent -> that parent becomes `parent_span_id`.
- 2+ causal parents -> `parent_span_id = null`; every causal parent becomes a span `Link`.

This avoids inventing a privileged parent at a Join and follows the OpenTelemetry trace model's support for Links in scatter/gather aggregation.

## Deterministic identifiers

If a valid ATL `trace.trace_id` / `trace.span_id` exists, reuse it. Otherwise derive stable lowercase hex IDs from SHA-256:

- trace id: first 32 hex chars of `sha256(run_id)`
- span id: first 16 hex chars of `sha256(event_id)`

This is an export projection identifier scheme, not a replacement for ATL `event_id`.

## Non-goals

- real OTLP exporter
- OpenTelemetry SDK dependency
- collector configuration
- network transport
- CloudEvents HTTP binding
- changing ATL schema or topology semantics
