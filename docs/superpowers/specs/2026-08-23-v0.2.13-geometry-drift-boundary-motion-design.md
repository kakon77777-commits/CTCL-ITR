# CTCL-ITR v0.2.13 — Geometry Drift & Boundary Motion Design

## Purpose

v0.2.12 turns one joint uncertainty surface into evidence-supported discrete geometry. v0.2.13 compares two compatible geometry snapshots and reports how the supported domain, sign regions, stability boundaries, connected components, and supported-edge gradients changed.

The reference comparison fixes the same baseline evidence and changes only the later observation:

```text
G0 = Geometry(base -> current)
G1 = Geometry(base -> later)
```

This keeps the reference frame stable. The release does not treat geometry motion as a causal mechanism or governance authority.

## Method

Method identifier:

```text
surface_geometry_drift_v1
```

Inputs:

1. base geometry report, schema `0.2.12`;
2. current geometry report, schema `0.2.12`;
3. drift spec, schema `0.2.13`.

The two geometry reports MUST agree on:

- `measurement_contract`;
- family names and ordering;
- grid method, `grid_step`, and minimum family weight;
- v0.2.12 geometry method;
- boundary interpolation contract.

A mismatch rejects comparison instead of coercing one geometry into the other.

## Supported-domain motion

For each subject, let $S_0$ and $S_1$ be the sets of resampling-supported cell keys in the base and current geometry snapshots.

Report:

$$
S_{persist}=S_0\cap S_1,
$$

$$
S_{gain}=S_1\setminus S_0,
$$

$$
S_{loss}=S_0\setminus S_1.
$$

Also report counts, net supported-cell change, union size, and Jaccard overlap:

$$
J(S_0,S_1)=\frac{|S_0\cap S_1|}{|S_0\cup S_1|}.
$$

`gained_supported_cells` means evidence support expanded at those declared grid cells. It does not imply universal capability expansion outside the declared grid.

## Connected-component split / merge diagnostics

Connected components are compared by member overlap.

For every base component, collect current components with non-empty member intersection. More than one overlap is reported as a descriptive split event.

For every current component, collect base components with non-empty member intersection. More than one overlap is reported as a descriptive merge event.

These are graph-component events under the declared grid and support rule, not physical phase transitions.

## Sign-region migration

For persistent supported cells only, report a transition matrix between:

```text
positive_band
negative_band
crosses_zero
zero_band
```

Gained supported cells are reported separately with their current class. Lost supported cells are reported separately with their base class.

This prevents support gain/loss from being falsely interpreted as a sign-class transition.

## Stability-boundary motion

Positive and negative stability zero-crossings from v0.2.12 are treated as interpolated boundary points.

Within each boundary type, v0.2.13 performs deterministic greedy nearest-point matching in simplex $L_1$ distance:

$$
d_1(w^{(0)},w^{(1)})=\sum_f |w_f^{(1)}-w_f^{(0)}|.
$$

Candidate pairs are sorted by:

1. ascending $L_1$ distance;
2. base boundary coordinate key;
3. current boundary coordinate key.

Each point may be used once. Unmatched current points are `appeared`; unmatched base points are `disappeared`.

For each match report:

- $L_1$ displacement;
- per-family signed displacement $w_f^{(1)}-w_f^{(0)}$;
- base/current interpolated coordinates.

This matching is descriptive nearest-point matching, not proof that two interpolated boundaries have persistent ontological identity.

## Support-frontier motion

v0.2.12 support-boundary edges are compared through their supported endpoint cells. Report persistent, appeared, and disappeared support-boundary edges, plus nearest supported-endpoint displacement when both snapshots contain support boundaries.

No position is interpolated into an unsupported region.

## Local-gradient drift

Supported-edge gradients are keyed by the unordered pair of endpoint cell keys. For edges present in both snapshots report:

$$
\Delta g_{ij}=g^{(1)}_{ij}-g^{(0)}_{ij}.
$$

Also report absolute change, band-lower slope change, and band-upper slope change. New/lost gradient edges are listed separately.

No gradient is synthesized for an edge absent from either snapshot.

## Reference scenario

The canonical later snapshot keeps `snapshot:base` fixed, then updates the later evidence:

- code family deep-point successes remain bracketed at 7/10;
- research family deep observed point improves from 28/40 to 30/40;
- research adds one deeper point with 15/40 successes;
- later backend id is `backend-gamma`;
- 256 deterministic resampling replicates are used for the later joint surface.

Expected qualitative geometry motion:

```text
supported cells:          6 -> 8
positive-band cells:      1 -> 5
crosses-zero cells:       5 -> 3
support frontier:         code 0.6/0.7 -> 0.8/0.9
positive stability edge:  moves toward lower code weight
```

## Epistemic boundary

```text
Geometry Drift != Causal Mechanism
Boundary Motion != Capability Velocity
Support Expansion != Universal Capability Expansion
Component Split/Merge != Physical Phase Transition
Nearest Boundary Match != Persistent Boundary Identity
Gradient Drift != Global Derivative Drift
Geometry Drift Report != Authority
```
