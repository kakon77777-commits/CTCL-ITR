# CTCL-ITR v0.2.7 Horizon Calibration & Evidence Profiles — Design

## Purpose

v0.2.6 made `Autonomy Horizon` and `Governance Horizon` explicit inputs under one measurement contract. v0.2.7 replaces hand-entered horizon depths with a reproducible calibration pipeline backed by repeated trials.

The release remains read-only and non-authoritative:

```text
Calibration != Authority
Evidence Profile != Policy Decision
Calibrated Horizon != Automatic Enforcement
```

## Why this slice exists

A horizon is a reliability statement, not a single observed duration and not one p95 latency. The runtime therefore needs repeated evidence across multiple interaction depths and a declared target reliability before it can derive a horizon.

The reference method deliberately avoids unsupported extrapolation. If the evidence does not bracket the target reliability, the calibrator returns an insufficient-support result instead of inventing a horizon.

## Measurement contract

The calibration suite carries one shared contract:

```json
{
  "unit": "interaction_depth",
  "reliability_p": 0.9,
  "scope_id": "reference-governance-scope",
  "assessment_method": "monotone_binomial_pava_v1"
}
```

Autonomy and governance evidence MUST use the same unit, reliability target, and scope before they may be combined into one v0.2.6 `GovernanceHorizonAssessment`.

## Input: HorizonCalibrationSuite

A suite contains grouped repeated-trial observations for two subjects:

- `autonomy`
- `governance`

Each evidence point contains:

- `depth`
- `trials`
- `successes`
- `evidence_refs[]`

The reference profile requires:

- at least 4 distinct depths per subject;
- at least 40 total trials per subject;
- at least 5 trials at every depth;
- nonnegative finite depths;
- `0 <= successes <= trials`.

## Reference calibration method

### 1. Aggregate and sort

Duplicate depths are aggregated by summing successes and trials. Evidence refs are unioned deterministically.

### 2. Empirical probability

For each depth $d_i$:

$$
\hat p_i = \frac{s_i}{n_i}.
$$

### 3. Wilson evidence interval

Each raw point receives a Wilson score interval at the declared evidence confidence level (default 90%). This interval is reported as evidence metadata; it is not silently converted into a horizon confidence interval.

### 4. Monotone calibration

The expected relationship is non-increasing success probability as interaction depth grows. The reference method applies weighted Pool Adjacent Violators Algorithm (PAVA), weighted by trial count, to obtain a monotone empirical reliability curve.

The method id is:

```text
monotone_binomial_pava_v1
```

### 5. Horizon crossing

For target reliability $p^*$, the horizon is the maximum supported depth at which the fitted curve reaches $p^*$.

If two adjacent fitted points bracket $p^*$, linear interpolation in the depth-probability plane is used.

No reference horizon is emitted when:

- all fitted probabilities remain above the target over the observed range;
- all fitted probabilities remain below the target;
- evidence minimums are not satisfied.

These states are explicit `support_status` values rather than extrapolated numbers.

## Output: HorizonEvidenceProfile

Each subject profile contains:

- trial and depth counts;
- raw empirical points;
- Wilson intervals;
- PAVA fitted points;
- target reliability;
- horizon depth or `null`;
- crossing bracket;
- support status;
- support reasons;
- full evidence-ref union.

The combined output contains a generated v0.2.6 `GovernanceHorizonAssessment` only if both subject profiles are sufficiently supported and both horizons are finite.

## Compatibility bridge

When both horizons are supported, v0.2.7 generates exactly the shape consumed by v0.2.6:

```text
HorizonCalibrationSuite
  -> HorizonEvidenceProfile[autonomy]
  -> HorizonEvidenceProfile[governance]
  -> GovernanceHorizonAssessment v0.2.6
  -> Governance Signals v0.2.6
```

This preserves the existing signal engine and keeps calibration separate from escalation policy.

## Reference evidence

The canonical example targets reliability `p = 0.9` and is constructed so the monotone empirical curve crosses at:

```text
H_A = 12 interaction-depth units
H_G = 9 interaction-depth units
Delta_AG = 3
```

This reproduces the v0.2.6 reference horizons, but now from repeated evidence rather than manually entered depths.

## Failure modes

The calibrator rejects:

- mismatched subject contracts;
- invalid trial counts;
- insufficient distinct depths;
- insufficient total trials;
- insufficient trials per depth;
- nonfinite depths;
- unsupported reliability targets;
- evidence that cannot bracket the target reliability.

## Non-goals

v0.2.7 does not:

- claim METR methodology equivalence;
- implement logistic regression;
- extrapolate beyond observed depth support;
- turn statistical evidence into authority;
- automatically change escalation policy;
- automatically suspend, revoke, resume, or commit actions.

## Future extensions

Possible later methods may include logistic/binomial fits, bootstrap uncertainty, hierarchical task-family calibration, or domain-specific external calibrators. They must remain explicit method profiles rather than silently changing the meaning of existing Horizon values.
