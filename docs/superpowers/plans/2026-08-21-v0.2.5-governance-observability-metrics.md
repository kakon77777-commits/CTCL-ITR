# CTCL-ITR v0.2.5 Governance Observability & Oversight Metrics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add read-only, policy-explicit governance metrics over ATL governance events and durable governance state.

**Architecture:** Implement a pure metrics analyzer in `ctcl_itr.governance_metrics`, expose read-only list methods from `SQLiteApprovalQueue`, validate a structured report with JSON Schema, and provide a CLI that can analyze either a durable SQLite store or a committed scenario file. Metrics never mutate governance state.

**Tech Stack:** Python 3.11+, standard library, SQLite, JSON Schema Draft 2020-12, pytest.

**Spec:** `docs/superpowers/specs/2026-08-21-v0.2.5-governance-observability-metrics-design.md`

## Global Constraints

- Preserve TemporalEvent and v0.2.3 governance object schemas unchanged.
- Metrics are read-only projections and cannot grant/revoke/resume authority.
- Explicit intervention deadlines override approval expiry; expiry fallback MUST be labeled `approval_expiry_proxy`.
- Risk/debt weights MUST be emitted in every report.
- Zero effective-transition denominator yields `null` Human Intervention Density.
- Use TDD: failing test before each production behavior.
