# CTCL-ITR v0.2.6 Governance Horizon & Escalation Signals — Design

**Date:** 2026-08-21  
**Status:** Approved design / implementation reference

## 1. Goal

Add a read-only governance signal layer above v0.2.5 metrics without changing authorization semantics.

The layer must:

- consume a v0.2.5 governance metrics report;
- consume an independently supplied Autonomy/Governance Horizon assessment under one explicit measurement contract;
- compute Autonomy–Governance Gap and Governance Margin;
- emit deterministic advisory escalation signals;
- distinguish explicit intervention-deadline breaches from approval-expiry proxies;
- never mutate ApprovalRequest, DecisionReceipt, AuthorityGrant, durable governance state, or ATL history.

## 2. Non-goals

v0.2.6 does not:

- infer Governance Horizon from one p95 latency;
- infer Autonomy Horizon from one successful run;
- grant or revoke authority;
- resume or cancel a run;
- implement a policy engine;
- auto-escalate to a human endpoint;
- change TemporalEvent or governance-object schemas.

## 3. Horizon contract

A horizon assessment is accepted only when Autonomy and Governance Horizons share one declared measurement contract:

```text
unit = interaction_depth
reliability_p
scope_id
assessment_method
```

Reference equations:

$$
\Delta_{AG}=H_A-H_G
$$

$$
M_G=H_G-H_A
$$

A positive $\Delta_{AG}$ means declared autonomy depth exceeds declared governance-control depth under the same contract. It is a diagnostic condition, not an automatic authorization rule.

## 4. Signal inputs

Inputs are:

1. `GovernanceMetricsReport v0.2.5`
2. `GovernanceHorizonAssessment v0.2.6`
3. `GovernanceEscalationPolicy v0.2.6`

HID is retained as context but receives no default threshold because more human intervention is not intrinsically better governance.

## 5. Signal set

The v0.2.6 reference signal set is deliberately small and directional:

1. `autonomy_governance_gap`
2. `effective_oversight_density_low`
3. `oversight_debt_high`
4. `escalation_latency_p95_high`
5. `explicit_intervention_deadline_breach`
6. `critical_oversight_coverage_low`

Each signal records:

```text
code
status = clear | breach | not_applicable
severity
observed
threshold
comparator
unit
rationale
evidence_ids[]
```

## 6. Explicit-deadline rule

Only v0.2.5 timing items with:

```text
timing_basis = explicit_intervention_deadline
```

count toward known harm-deadline breach signals.

Items labeled:

```text
timing_basis = approval_expiry_proxy
```

remain observable but are not promoted into known harm-propagation failures.

## 7. Overall escalation projection

`overall_level` is the maximum declared severity among breached signals.

Reference mapping:

```text
clear    -> none
info     -> watch
low      -> watch
medium   -> review
high     -> priority_review
critical -> urgent_human_review
```

The report must include:

```text
non_authoritative = true
```

Therefore:

```text
Signal != Authority
Signal != Automatic Enforcement
```

## 8. Reference assessment

Reference Horizon input:

```text
H_A = 12 interaction-depth units
H_G = 9 interaction-depth units
p = 0.9
```

Derived:

```text
Delta_AG = 3
M_G = -3
```

Combined with the v0.2.5 reference metrics, all six reference signal conditions breach and the resulting advisory level is `critical` with `urgent_human_review`.

## 9. Storage and compatibility

v0.2.6 introduces only read-only JSON artifacts and a pure analyzer. It adds no SQLite tables and no mutable runtime state.

Compatibility requirements:

- TemporalEvent unchanged;
- ApprovalRequest unchanged;
- DecisionReceipt unchanged;
- AuthorityGrant unchanged;
- SQLite governance mutation semantics unchanged;
- v0.2.5 GovernanceMetricsReport remains the observability input;
- v0.2.4 durable store and earlier topology/observability/integrity layers remain valid.

## 10. Testing

TDD must cover:

- positive and non-positive gap/margin;
- all six signal conditions;
- clear profile;
- invalid / mismatched horizon contract;
- explicit deadline vs approval-expiry proxy distinction;
- immutability of input objects;
- schema validation;
- exact reference regeneration;
- module CLI and installed entry point;
- v0.2.5 regression compatibility.
