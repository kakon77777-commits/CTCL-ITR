# CTCL-ITR v0.2.2 Ledger Integrity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build a sidecar SHA-256 hash chain, trusted ledger anchor, verification API, CLI, schemas, reference artifacts, and release validation for ATL JSONL ledgers.

**Architecture:** Keep TemporalEvent immutable and unchanged. Hash exact nonblank JSONL record bytes, store one sidecar IntegrityRecord per event, and bind the final chain head plus event count into a LedgerAnchor. Verification checks event/sidecar correspondence, chain links, digests, order, and optional anchor consistency.

**Tech Stack:** Python 3.11+, standard library `hashlib/json/argparse/pathlib`, JSON Schema Draft 2020-12, pytest.

**Spec:** `docs/superpowers/specs/2026-08-20-v0.2.2-ledger-integrity-design.md`

## Global Constraints

- Do not modify the core TemporalEvent schema for integrity fields.
- Use SHA-256 with textual form `sha256:<64 lowercase hex>`.
- Hash exact JSONL record bytes excluding the line terminator; reject blank records.
- Genesis previous chain digest is 32 zero bytes.
- Use the domain separator `CTCL-ITR/ATL/CHAIN/v0.2.2\0`.
- Tail truncation is considered detectable only when the original trusted anchor is supplied.
- Do not claim RFC 8785 conformance or Merkle-tree properties.
- Existing topology and observability behavior must remain unchanged.
