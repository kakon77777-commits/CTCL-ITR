# CTCL-ITR v0.2.14 Geometry Motion Stability & Multi-Snapshot Trajectories Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a deterministic, read-only multi-snapshot geometry trajectory analyzer above the v0.2.13 pairwise drift contract.

**Architecture:** Accept >=3 compatible v0.2.12 geometry reports plus an ordered v0.2.14 trajectory spec. Reuse `compare_surface_geometry()` for each consecutive pair, then aggregate support direction/reversals, boundary/component lineages, sign persistence, and local-gradient trajectories without synthesizing evidence across unsupported cells.

**Tech Stack:** Python 3.11+, stdlib, jsonschema Draft 2020-12, pytest.

**Spec:** `docs/superpowers/specs/2026-08-23-v0.2.14-geometry-motion-trajectories-design.md`

## Global Constraints

- Read-only and non-authoritative.
- At least 3 observations; timestamps strictly increasing.
- All geometry contracts must be v0.2.12-compatible.
- Consecutive motion delegates to v0.2.13 `compare_surface_geometry()`.
- Boundary/component matching remains descriptive, not identity.
- No interpolation through unsupported cells.
- No new runtime dependency.
