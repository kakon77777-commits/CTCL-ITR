# CTCL-ITR v0.2.4 Durable Governance Store — Design

## Goal
Persist v0.2.3 ApprovalRequest, DecisionReceipt, and AuthorityGrant state across process restarts without changing their semantic contracts.

## Architecture

`SQLiteApprovalQueue` mirrors the public mutation/query surface of the in-memory `ApprovalQueue`, but stores canonical JSON payloads plus indexed state in SQLite. Every mutating operation runs in a transaction; authority consumption/revocation uses `BEGIN IMMEDIATE` so read-modify-write is atomic for the reference single-database runtime.

The store keeps four tables:

- `governance_approval_requests`
- `governance_decision_receipts`
- `governance_authority_grants`
- `governance_mutations` (append-only mutation journal)

The three semantic object payloads remain the same v0.2.3 schemas. Durability metadata (`state_version`, timestamps, indexed status/use counters) belongs to the store, not to the canonical object schemas.

## Invariants

1. Restart does not lose pending approvals, receipts, grants, use counts, or revocation state.
2. `resolve(receipt, grant)` is atomic: either request status + receipt + optional grant all commit, or none do.
3. Duplicate approval IDs, decision IDs, and authority refs remain rejected after restart.
4. Authority consumption is atomic and never exceeds `max_uses`.
5. Revocation survives restart.
6. Expiration survives restart and only transitions pending requests.
7. SQLite storage is a projection of governance state, not the ATL canonical event history.
8. The mutation journal is append-only reference evidence; it does not replace ATL or the v0.2.2 integrity chain.

## SQLite profile

- `PRAGMA foreign_keys = ON`
- `PRAGMA journal_mode = WAL`
- `PRAGMA synchronous = FULL`
- explicit transactions for multi-object mutations
- JSON payloads stored as compact UTF-8 JSON text

## Recovery

Re-opening the same database path must expose the same queue state through `pending`, `get_request`, `get_receipt`, and `get_grant`. No replay of private reasoning or prompt content is required.

## CLI

`ctcl-itr-governance-store demo --db <path>` creates a reference approval, persists it, resolves it, closes/reopens the store, and reports recovered authority and resume eligibility.

`ctcl-itr-governance-store status --db <path>` reports object and mutation counts.

## Non-goals

- distributed consensus;
- multi-node leases/fencing;
- remote database support;
- governance metrics/oversight debt;
- new approval semantics;
- signed governance receipts.
