# CTCL-ITR v0.2.3 Governance Core Design

## Goal

Turn human checkpoints into explicit, auditable runtime objects without changing canonical TemporalEvent semantics.

## Core objects

- `ApprovalRequest`: trigger, action, target, risk, evidence, requested authority, expiry.
- `DecisionReceipt`: principal, decision, selected option, human active/governance time.
- `AuthorityGrant`: bounded scope, target, expiry, max uses, revocability.

An approval does not itself equal authority.

## State machines

```text
pending -> approved | denied | modified | deferred | cancelled | expired
active authority -> consumed | revoked | expired
```

## Resume eligibility

A suspended run may resume only when the decision authorizes the action and a linked active grant matches action/target, is unexpired/unrevoked, and has remaining uses. The evaluator returns structured rejection reasons.

## Event integration

Canonical TemporalEvent remains unchanged. Existing ATL events reference governance IDs:

- `human.checkpoint.requested` -> `approval_id`
- `human.checkpoint.resolved` -> `decision_id`
- `authority.checked` -> `authority_ref`
- `run.resumed` -> `decision_id`, `authority_ref`

## Non-goals

No distributed queue, UI transport, cryptographic human identity proof, multi-party quorum, or general policy engine in v0.2.3.
