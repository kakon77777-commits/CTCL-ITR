# Geometry Drift & Boundary Motion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a deterministic, evidence-preserving comparison layer for v0.2.12 geometry snapshots that measures support-domain change, component split/merge, sign-region migration, stability-boundary displacement, support-frontier movement, and local-gradient drift.

**Architecture:** Add one dependency-free `ctcl_itr.calibration_geometry_drift` module above v0.2.12. It consumes already-derived geometry reports and never redefines the underlying uncertainty surface or geometry algorithm. Canonical later geometry is generated from a fixed base snapshot plus new later evidence through the existing v0.2.11 and v0.2.12 pipelines.

**Tech Stack:** Python standard library, pytest, JSON Schema Draft 2020-12/jsonschema, existing CTCL-ITR calibration/surface modules.

**Spec:** `docs/superpowers/specs/2026-08-23-v0.2.13-geometry-drift-boundary-motion-design.md`

## Global Constraints

- Package version becomes exactly `0.2.13`.
- New method id is exactly `surface_geometry_drift_v1`.
- No interpolation into unsupported regions.
- No causal or authority claim.
- No new runtime dependency.
- Existing v0.2.12 geometry and all earlier contracts remain backward compatible.
