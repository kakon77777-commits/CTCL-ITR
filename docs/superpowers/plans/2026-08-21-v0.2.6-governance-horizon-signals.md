# Governance Horizon & Escalation Signals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a deterministic, read-only Governance Horizon and escalation-signal layer above CTCL-ITR v0.2.5 metrics.

**Architecture:** A new dependency-light `ctcl_itr.governance_signals` module consumes a v0.2.5 metrics report, a separate horizon assessment, and a threshold policy. It computes `H_A-H_G`, explicit intervention-deadline breaches, directional threshold signals, and an advisory aggregate escalation level without mutating governance state.

**Tech Stack:** Python 3.11+, stdlib JSON/datetime, JSON Schema Draft 2020-12, pytest.

**Spec:** `docs/superpowers/specs/2026-08-21-v0.2.6-governance-horizon-signals-design.md`

## Global Constraints

- `TemporalEvent`, `ApprovalRequest`, `DecisionReceipt`, and `AuthorityGrant` schemas remain unchanged.
- Signals are read-only and non-authoritative.
- Horizon values are assessment inputs; v0.2.6 does not infer them from p95 latency.
- Only explicit intervention deadlines count as harm-deadline breaches.
- Existing v0.2.5 metrics remain the canonical observability input.
- Use test-first RED → GREEN cycles for production behavior.
