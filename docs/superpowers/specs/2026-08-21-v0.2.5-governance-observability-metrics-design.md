# CTCL-ITR v0.2.5 Governance Observability & Oversight Metrics — Design

**Date:** 2026-08-21  
**Status:** Approved implementation design  
**Base:** CTCL-ITR v0.2.4 Durable Governance Store

## Goal

Add a read-only governance observability layer that computes interpretable oversight metrics from existing ATL events, ApprovalRequest, DecisionReceipt, AuthorityGrant, and durable SQLite governance state without changing governance authorization semantics.

## Architectural Boundary

```text
Governance decisions != Governance metrics
Governance metrics != Authorization policy
Observation != Authority
```

Metrics may diagnose weak, slow, overloaded, or incomplete governance. They MUST NOT independently grant, revoke, resume, or commit actions.

## Inputs

The analyzer consumes:

- `approval_requests[]`
- `decision_receipts[]`
- `authority_grants[]`
- optional ATL `events[]`
- observation time `at`
- optional per-approval `intervention_deadlines{approval_id: datetime}`
- explicit `MetricsPolicy`

The durable store gains read-only list APIs so a reopened SQLite state can be analyzed without reconstructing object IDs externally.

## Metrics Policy

Default risk weights:

```text
low=1
medium=2
high=4
critical=8
```

Default debt multipliers:

```text
unresolved=1.0
overdue=1.0 additional
deferred=0.5
stale_authority=1.0
```

All weights and multipliers are emitted in the report. They are measurement policy, not ontology.

## Human Intervention Density

Define effective transition count from an explicit event-type contract.

Default effective transitions:

```text
action.completed
validation.completed
commit.confirmed
human.checkpoint.resolved
```

Then:

$$
\rho_H=
\frac{N_{human.checkpoint.resolved}}
{N_{effective\ transitions}}
$$

If the denominator is zero, the metric is `null`, not zero.

## Effective Oversight Density

An oversight opportunity is an ApprovalRequest. A request counts as effectively reviewed when it has a linked DecisionReceipt with a terminal oversight decision:

```text
approve
deny
modify
cancel
```

and the decision is not later than the applicable intervention deadline.

Risk-weighted EOD:

$$
EOD = \frac{\sum_i w_i I(reviewed_i)}{\sum_i w_i}
$$

`defer` is a human interaction but not a closed oversight obligation, so it does not satisfy effective review.

## Escalation Latency

For resolved requests:

$$
L_i = t_{decision,i}-t_{request,i}
$$

Report count, mean, p50, p95, max, and per-request values. Pending requests are reported as censored/open age and are not mixed into resolved latency statistics.

## Intervention Timing

Each request has an applicable deadline:

1. explicit `intervention_deadline_at` if supplied;
2. otherwise `ApprovalRequest.expires_at` as an `approval_expiry_proxy`.

For a resolved request:

$$
R_i = \frac{t_{decision}-t_{request}}{t_{deadline}-t_{request}}
$$

and:

$$
M_i=t_{deadline}-t_{decision}
$$

Report:

- `timing_ratio`
- `margin_ms`
- `timely`
- `timing_basis`

A negative margin means the intervention arrived after the applicable deadline.

## Oversight Debt

v0.2.5 defines a measurable operational debt vector:

```text
unresolved_weight
 overdue_weight
 deferred_weight
 stale_authority_weight
 total_weight
```

Where:

- unresolved: request has no closing decision;
- overdue: unresolved request is past applicable deadline;
- deferred: latest linked receipt is `defer`;
- stale authority: grant is still `active` even though observation time is past grant expiry.

`total_weight` applies the declared MetricsPolicy multipliers. The vector remains canonical for diagnosis; the scalar is only a policy projection.

## Human Governance Time

Aggregate `human_governance_ms` and `human_active_ms` from DecisionReceipt objects. Report total, mean, and count.

## Risk-Class Coverage

For each risk class report:

```text
opportunities
closed
open
weighted_coverage
```

This prevents a high aggregate EOD from hiding poor coverage of critical items.

## Durable Store Integration

`SQLiteApprovalQueue` adds read-only methods:

```python
list_requests(status: str | None = None) -> list[dict]
list_receipts() -> list[dict]
list_grants() -> list[dict]
```

They do not mutate state and preserve v0.2.4 persistence semantics.

## CLI

```bash
ctcl-itr-governance-metrics \
  --db governance.sqlite3 \
  --events governance_checkpoint.events.jsonl \
  --at 2026-08-21T00:00:00+00:00
```

The CLI outputs one JSON report and exits nonzero on malformed input.

A file-mode is also supported:

```bash
ctcl-itr-governance-metrics \
  --scenario examples/governance_metrics_scenario.json
```

## Reference Scenario

The committed scenario includes multiple risk levels and outcomes:

- timely medium approval;
- timely high denial;
- critical unresolved overdue request;
- high deferred request;
- expired-but-still-active authority grant.

This produces nontrivial EOD, latency, timing, and debt values.

## Report Contract

A new JSON Schema Draft 2020-12 file `schemas/governance-metrics-report.schema.json` validates the report.

The report MUST include:

```text
schema_version
observed_at
policy
human_intervention_density
effective_oversight_density
escalation_latency
intervention_timing
oversight_debt
human_time
risk_coverage
counts
```

## Compatibility

- TemporalEvent schema unchanged.
- Governance request/receipt/grant schemas unchanged.
- v0.2.4 durable mutations unchanged.
- Metrics are read-only projections.
- v0.2.2 integrity and v0.2.1 observability remain applicable.

## Non-goals

v0.2.5 does not add:

- automated policy changes based on metrics;
- automatic escalation execution;
- subjective quality scoring of human decisions;
- claim that approval expiry equals physical harm-propagation deadline;
- cross-organization benchmarking standards.
