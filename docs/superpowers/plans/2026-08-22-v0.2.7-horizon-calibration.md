# CTCL-ITR v0.2.7 Horizon Calibration & Evidence Profiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Derive v0.2.6-compatible Autonomy/Governance Horizons from repeated interaction-depth evidence using a transparent monotone empirical calibration profile.

**Architecture:** Add one dependency-free `horizon_calibration` module. It validates grouped binomial evidence, computes Wilson point intervals, applies weighted non-increasing PAVA, derives target-reliability crossings only when bracketed by observed evidence, and emits evidence profiles plus an optional v0.2.6 `GovernanceHorizonAssessment`. Existing signal semantics remain unchanged.

**Tech Stack:** Python 3.11+, stdlib (`math`, `statistics`, `json`, `argparse`), JSON Schema Draft 2020-12, pytest.

**Spec:** `docs/superpowers/specs/2026-08-22-v0.2.7-horizon-calibration-design.md`

## Global Constraints

- No new runtime dependency.
- Unit remains exactly `interaction_depth`.
- Reference method id is exactly `monotone_binomial_pava_v1`.
- No extrapolated horizon when target reliability is not bracketed by observed evidence.
- Calibration outputs are non-authoritative.
- v0.2.6 GovernanceHorizonAssessment shape remains consumable by `governance_signals`.
- TemporalEvent and governance object schemas remain unchanged.
