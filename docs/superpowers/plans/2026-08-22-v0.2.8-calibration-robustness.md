# CTCL-ITR v0.2.8 Calibration Robustness, Drift & Task-Family Profiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compare evidence-backed Horizon calibration snapshots across task-family mixtures and backends while separating observed-mixture drift from fixed-reference composition-adjusted drift.

**Architecture:** Add one dependency-free `calibration_robustness` module above v0.2.7. It calibrates each family with the existing v0.2.7 engine, interpolates supported family reliability curves only inside observed support, builds observed/reference weighted mixture curves, and emits pairwise drift/robustness diagnostics. Existing calibration, signal, governance, and authority semantics remain unchanged.

**Tech Stack:** Python 3.11+, stdlib (`datetime`, `json`, `argparse`, `copy`, `math`), existing `ctcl_itr.horizon_calibration`, JSON Schema Draft 2020-12, pytest.

**Spec:** `docs/superpowers/specs/2026-08-22-v0.2.8-calibration-robustness-design.md`

## Global Constraints

- No new runtime dependency.
- v0.2.7 method id remains `monotone_binomial_pava_v1`.
- No family-curve extrapolation beyond observed support.
- Fixed reference weights must be explicit and normalized by the implementation.
- Composition-adjusted drift is descriptive, not causal attribution.
- Cross-backend comparison must be labeled as such.
- No governance authority mutation.
- v0.2.7 calibration artifacts remain valid and unchanged.
