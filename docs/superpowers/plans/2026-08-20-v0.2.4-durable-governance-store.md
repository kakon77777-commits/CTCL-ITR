# CTCL-ITR v0.2.4 Durable Governance Store Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox syntax for tracking.

**Goal:** Add a restart-safe SQLite governance queue compatible with v0.2.3 semantics.

**Architecture:** A new `SQLiteApprovalQueue` persists governance objects and state transitions transactionally. Canonical governance JSON objects remain unchanged; SQLite-only state/version metadata and an append-only mutation journal provide durable operational state.

**Tech Stack:** Python 3.10+, stdlib `sqlite3`, existing pytest/jsonschema stack.

**Spec:** `docs/superpowers/specs/2026-08-20-v0.2.4-durable-governance-store-design.md`

## Global Constraints

- Do not change TemporalEvent semantics.
- Do not change v0.2.3 governance object schemas.
- Use SQLite from the Python standard library only.
- Multi-object resolve must be transactional.
- Authority consumption/revocation must survive restart.
- Existing v0.1-v0.2.3 tests must remain green.
