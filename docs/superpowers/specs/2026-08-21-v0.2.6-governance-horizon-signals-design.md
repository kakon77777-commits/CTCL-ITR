# CTCL-ITR v0.2.6 — Governance Horizon & Escalation Signals Design

**Date:** 2026-08-21  
**Status:** Approved implementation design  
**Base:** CTCL-ITR v0.2.5 Governance Observability & Oversight Metrics

## 1. Goal

Add a read-only signal layer above v0.2.5 governance metrics that compares an externally supplied Autonomy Horizon and Governance Horizon under one measurement contract, computes the Autonomy–Governance Gap, and emits deterministic escalation signals from declared thresholds.

The release must preserve:

```text
Observation != Authority
Metric != Policy Decision
Signal != Authority
Signal != Automatic Enforcement
```

## 2. Non-goals

v0.2.6 does not:

- derive Autonomy Horizon from a single latency metric;
- derive Governance Horizon from a single run;
- grant, revoke, consume, suspend, resume, or commit authority;
- mutate ApprovalRequest / DecisionReceipt / AuthorityGrant state;
- alter TemporalEvent or governance object schemas;
- implement policy enforcement or automatic circuit breaking.

## 3. Horizon assessment contract

A `GovernanceHorizonAssessment` carries two comparable values under one explicit measurement contract:

```text
H_A = autonomy_horizon_depth
H_G = governance_horizon_depth
```

Required contract fields:

```text
unit = interaction_depth
reliability_p in (0, 1]
scope_id
assessment_method
assessed_at
evidence_refs[]
```

v0.2.6 intentionally accepts horizon values as assessment inputs rather than pretending to infer them from the v0.2.5 report.

Derived quantities:

$$
\Delta_{AG}=H_A-H_G
$$

$$
M_G=H_G-H_A=-\Delta_{AG}
$$

A positive `autonomy_governance_gap` means delegated depth exceeds the assessed governance depth under the same contract.

## 4. Signal policy

`GovernanceEscalationPolicy` contains directional thresholds only:

```text
max_autonomy_governance_gap
min_effective_oversight_density
max_oversight_debt
max_escalation_p95_ms
max_explicit_deadline_breaches
min_critical_oversight_coverage
```

Human Intervention Density is reported as context but receives no default pass/fail threshold because lower intervention density is not intrinsically better governance.

Each threshold also carries a declared signal severity. v0.2.6 fixed severities are:

```text
info < low < medium < high < critical
```

## 5. Explicit deadline breach semantics

Only `intervention_timing.items[]` whose `timing_basis` is `explicit_intervention_deadline` count toward `explicit_deadline_breaches`.

A breach occurs when:

1. a decision exists and `timely == false`; or
2. no closing decision exists and `metrics_report.observed_at > deadline_at`.

Approval-expiry proxy misses remain observable in v0.2.5 but do not masquerade as known harm-propagation deadline breaches.

## 6. Signal report

`GovernanceSignalReport` contains:

```text
schema_version
observed_at
horizon
context_metrics
signals[]
overall_level
recommended_escalation
non_authoritative = true
policy
```

Every signal contains:

```text
code
status = clear | breach | not_applicable
severity
observed
threshold
comparator
unit
rationale
```

Reference signal codes:

```text
autonomy_governance_gap
effective_oversight_density_low
oversight_debt_high
escalation_latency_p95_high
explicit_intervention_deadline_breach
critical_oversight_coverage_low
```

## 7. Overall escalation projection

`overall_level` is the maximum severity among breached signals. If there are no breaches it is `clear`.

Deterministic recommendation projection:

```text
clear    -> none
low      -> watch
medium   -> review
high     -> priority_review
critical -> urgent_human_review
```

This field is advisory text. It is not an executable governance action.

## 8. Reference scenario

Use the committed v0.2.5 governance metrics report with:

```text
H_A = 12
H_G = 9
reliability_p = 0.90
unit = interaction_depth
```

Reference thresholds:

```text
max_autonomy_governance_gap = 0
min_effective_oversight_density = 0.50
max_oversight_debt = 20
max_escalation_p95_ms = 1,800,000
max_explicit_deadline_breaches = 0
min_critical_oversight_coverage = 0.75
```

Expected reference breaches: all six signal classes, with `overall_level = critical` and `recommended_escalation = urgent_human_review`.

## 10. Acceptance criteria

1. Horizon gap and margin are deterministic.
2. Horizon unit / probability / nonnegative-depth validation rejects invalid contracts.
3. Explicit deadline breach counting distinguishes explicit deadlines from expiry proxies.
4. All six reference signals are deterministic and schema-valid.
5. Inputs are not mutated.
6. Report always states `non_authoritative=true`.
7. CLI emits the exact committed reference report.
8. v0.2.5 focused tests remain green.
9. Full suite and pack validators pass before release.
